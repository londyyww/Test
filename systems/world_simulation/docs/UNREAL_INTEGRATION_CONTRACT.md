# Unreal Engine 5.8.4 Integration Contract

**Status: specification only.** Nothing in this module has been compiled with
UBT/UHT, run in the Unreal Editor, or tested over a real network. The portable
core compiles with `-fno-exceptions -fno-rtti` (`make ue-compat`), and avoids
C++20 keywords such as `requires` as identifiers because Unreal 5.x builds as
C++20. Everything below is the intended binding and must be validated on the
developer's machine.

## Module layout (proposed)

```
Source/LastLightWorld/                       (Runtime module, server + client)
  ThirdParty/llws/  -> systems/world_simulation/{include,src}, world_intelligence/include + src/Ini.cpp
  Public/LLWorldSimSubsystem.h               UWorldSubsystem (server only: ShouldCreateSubsystem checks NM_Client)
  Public/LLLootContainerComponent.h          UActorComponent on container actors
  Public/LLWorldEntityComponent.h            optional: binds an actor to a world-simulation entity id
  Private/LLMissionWorldHost.cpp             wraps llws::MissionWorldHost with the existing WorldIntelligence instance
```

Third-party sources compile with `bEnableExceptions = false` and RTTI off (the
defaults). Wrap portable headers in `THIRD_PARTY_INCLUDES_START/END` if the
project's warning level flags them.

## Authority

| Object | Server | Client |
|---|---|---|
| `ContainerService`, `WorldSimulation`, `MissionWorldHost` | owns, steps at the fixed simulation rate (30 Hz) | **never constructed** |
| Container contents (`LootResult`) | generated on search completion | sent only to entitled viewers |
| Search claims, grants | decided here | presentation only |

## Content and identity

* Content INI files ship as non-asset data (`Content/LastLight/WorldData/*.ini`,
  added to *Additional Non-Asset Directories to Package*), and load at server start
  with `llcontent::LoadAndValidate`. Validation errors fail the map load in
  development builds.
* Container actors carry `FName ContainerId` matching `[container.<ID>]`. Actor
  placement may override the position. In that case, call
  `ContainerService::UpdatePlayerPosition` with Unreal positions and keep content
  positions in sync (one source of truth to be decided by the team).
* `IItemCatalog` is implemented over the **authoritative item catalog**, a
  DataTable or Primary Data Assets keyed by the same stable item ids. Do not ship
  `FixtureItemCatalog`.

## RPC surface (on the player controller or an interaction component)

```cpp
UFUNCTION(Server, Reliable) void ServerLootRequest(FName ContainerId, uint8 Action, uint32 Sequence, uint32 Slot);
UFUNCTION(Client, Reliable) void ClientLootResult(FName ContainerId, uint32 Sequence, uint8 ResultCode);
UFUNCTION(Client, Reliable) void ClientContainerContents(FName ContainerId, const TArray<FLLLootItemView>& Items);
```

* `Sequence` is a per-player monotonic counter generated by the client. The server
  rejects repeats (`RejectedDuplicate`). Unreal's reliable RPC already deduplicates
  at the transport level, so this guards against gameplay-level resubmission and
  reconnect replays.
* `FLLLootItemView` contains item id, quantity, integrity, fill, grade and slot
  state, mapped 1:1 from `LootItem` and `SlotView`.
* Contents go to a client only after **that** viewer's instance is Searched:
  `Contents(c, viewer) != nullptr`.

## Replication

| Data | Mechanism |
|---|---|
| Container search state (Unsearched / Searching / Searched), discovered, cleared | replicated properties on `ULLLootContainerComponent`, updated from `ILootObserver` events |
| Slot states for open UIs | Client RPC on change (`ItemTaken / ItemReserved / ItemReturned`) |
| World entity state for presentation (lights, alarms, doors) | **already replicated** by the power-grid replication of PR #2; world-simulation states are server-side intent and are replicated only when presentation needs them |

## Inventory hand-off (`ILootGrantPort`)

The inventory team implements:

```cpp
GrantOutcome Grant(const LootGrant& g);   // idempotent per g.grantId
```

* `Accepted`: added now. `AlreadyApplied`: this `grantId` was applied earlier.
* `Rejected`: permanent refusal (no space). The item stays in the container.
* `Unavailable`: transient failure. The loot service retries the **same**
  `grantId` (bounded per step).

The loot system never decrements, moves or persists items after a grant.

## AI hand-off

* `IWorldSimObserver::OnPatrolDirective`: a Behavior Tree / StateTree service, or
  the squad layer, receives `{group, kind, area, target, central}`. Navigation,
  perception and combat remain Unreal AI and Tactical AI responsibilities. A
  directive is an *intention*, not a move order.
* Map world-simulation patrol groups to spawned robot squads by id (for example a
  `FName PatrolGroupId` on the squad spawner). Spawning and despawning robots by
  tier is a game decision. The simulation keeps the abstract group consistent either way.
* `ReportObserved(entity)` should be called by the server when a player perceives
  a world entity (line-of-sight checks already exist in game code).

## Mission Director hand-off

| Mission Director | World simulation |
|---|---|
| raid start (seed, persisted records) | `BeginRaid(seed, records)` and `ContainerService::BeginRaid(seed)` |
| scripted beat ("facility seals") | `ApplyMissionOverride(entity, Lockdown, ticks)` or `NotifySignal` |
| mission complete / extraction | `CompleteMission()`, `ContainerService::EndRaid()`, `ExportPersistentState()` → persistence service |
| world reset (lobby) | `ResetWorld()` |

## Hardware target (GTX 1660 Super 6GB, i5-10400F, 16 GB)

The portable core has been measured in a Linux sandbox only (see
`VERIFICATION_REPORT.md`). Those numbers do not translate to frame rates.
Profile in Unreal Insights with the `LLWorldSim` stat group around
`MissionWorldHost::Step`, at 5,000 entities, with four players, on the target
CPU.
